# Web Applications, Frontend, Browser & Client Runtime Security

## 1. Architecture & Exception Handling (OWASP Top 10:2025, ASVS v5.0.0)
- `[YELLOW]` **No ASVS Baseline / Fail-Open Exceptions (`A10:2025`):** Select an OWASP ASVS v5.0.0 assurance level (Level 2 default for apps handling sensitive data) and map V1–V17 controls upfront. Ensure global error handlers catch exceptions fail-closed and never return stack traces, SQL strings, or internal paths in production HTTP `400`/`500` responses.
- `[RED]` **Fail-Open Exception Bypass (`A10:2025`):** Never let `catch` blocks silently skip authentication, signature validation, or authorization checks.

## 2. Public Frontend Secrets, Bundles & Source Maps
- `[RED]` **Privileged Keys in Public Env Vars or Built Bundles (`CWE-798`, `CWE-312`):** Build tools (`Next.js`, `Vite`, `Expo`, `CRA`, `Nuxt`) inline `NEXT_PUBLIC_*`, `VITE_*`, `EXPO_PUBLIC_*`, `REACT_APP_*`, and `NUXT_PUBLIC_*` into public client JavaScript. Never place `SERVICE_ROLE`, Stripe `sk_*`, OpenAI/Anthropic/Gemini API keys, DB URLs, or signing secrets in frontend code or public env prefixes. Proxy privileged third-party calls through backend endpoints.
- `[RED]` **Client Public Keys Without Backend RLS/Rules:** Intentional public client identifiers (Supabase `anon`, Firebase web config, Stripe `pk_*`) must be backed by strict server-side authorization or database Row-Level Security / Firebase Security Rules; verify policies exist in the repo or flag as `[RED]`/`Unverified`.
- `[RED]` **Web-Root `.env`, `.git` & Backup/Dump Exposure (`CWE-530`):** Never copy `.env*`, `.git/`, or backup/database dump files (`*.bak`, `*.sql`, `*.dump`, `*.old`, `*.orig`) into `public/`, `static/`, `www/`, `htdocs/`, `dist/`, or Docker web roots served directly by Nginx/Apache/CDN.
- `[YELLOW]` **Public Production Source Maps (`*.js.map`, `*.css.map`):** Disable public source map emission (`productionBrowserSourceMaps: false`, Vite `build.sourcemap: false` or `'hidden'`) in production or upload `.map` files solely to private error-tracking storage.
- `[YELLOW]` **Directory Listings & CMS/Plugin Exposure (`CWE-548`):** Disable web-server directory indexing (`autoindex off` in Nginx, no `Options +Indexes` in Apache, no `serve-index` on public paths), strip CMS version meta generators, disable WordPress/CMS `xmlrpc.php` (multicall brute-force/pingback SSRF), disable in-dashboard file/plugin editors (`DISALLOW_FILE_EDIT`/`DISALLOW_FILE_MODS`), restrict CMS REST user enumeration (`/wp-json/wp/v2/users`), remove abandoned plugins (do not merely deactivate), and ban pirated ("nulled") themes/plugins.

## 3. Injection & Client-Side Execution
- `[RED]` **XSS (`CWE-79`, `A05:2025`):** Ban `eval()`, `new Function()`, `document.write()`, string `setTimeout`/`setInterval`, and unsanitized `dangerouslySetInnerHTML`, `v-html`, or `[innerHTML]`. Use framework auto-escaping and safe DOM APIs (`textContent`). Validate dynamic `href`/`src` attributes to allow `https:`/`http:`/`mailto:` only (block `javascript:`/`data:`).
- `[RED]` **Rich HTML, mXSS, DOM Clobbering & Service Worker Cache/Scope Isolation (`CWE-79`, `CWE-451`):** When rich HTML rendering is required, sanitize immediately before insertion with up-to-date **DOMPurify** (avoiding mXSS and script-gadget patterns) using strict tag/attribute allowlists (forbid or prefix `id`/`name`), enforce **Trusted Types** via CSP (`require-trusted-types-for 'script'; trusted-types app-policy dompurify;`), freeze config objects (`Object.freeze`), verify globals are not DOM nodes (`!('nodeType' in obj)`), and never pass untrusted URLs or overly broad `Service-Worker-Allowed` scopes to `navigator.serviceWorker.register()`. Key Service Worker caches by account/tenant/auth state and purge Service Worker, IndexedDB, `BroadcastChannel`, and `localStorage`/`sessionStorage` state on logout or account switch.
- `[RED]` **SSTI & Client-Side Template Injection (`CWE-1336`, `CWE-79`, `CWE-94`):** Never concatenate user input into server template strings (`Template(user_str).render()`), and never render untrusted input inside client-evaluated templates (`ng-app` / AngularJS expressions or runtime `Vue.compile`/Handlebars client compilers). Render static template files with typed context data and enable sandboxed template modes.
- `[RED]` **Prototype Pollution (`CWE-1321`):** Use `Map`/`Set` or `Object.create(null)` for dynamic lookup tables; reject `__proto__`, `constructor`, and `prototype` keys in deep-merge/clone/query parsers.

## 4. Browser Security Boundaries & HTTP Headers
- `[RED]` **Permissive CORS & Legacy JSONP (`CWE-942`):** Disable CORS by default on same-origin apps and retire legacy JSONP (`?callback=`) endpoints. When cross-origin API calls are required, match `Origin` against an exact server-side allowlist (never reflect arbitrary `Origin`, never allow `Origin: null`, never combine `*` with `Access-Control-Allow-Credentials: true`), and return `Vary: Origin`.
- `[YELLOW]` **Missing Security Headers (`A02:2025`):**
  - `Content-Security-Policy: default-src 'self'; script-src 'nonce-<RANDOM>' 'strict-dynamic'; object-src 'none'; base-uri 'none'; frame-ancestors 'none';` (fresh >=128-bit CSPRNG nonce per request; avoid `'unsafe-inline'`/`'unsafe-eval'`)
  - `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload` (RFC 6797, HTTPS only)
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY` (legacy fallback paired with `frame-ancestors 'none'`)
  - `Cross-Origin-Resource-Policy: same-origin` (or `same-site` / `cross-origin` for intentional public CDN assets)
  - `Referrer-Policy: strict-origin-when-cross-origin` (`no-referrer` on auth/reset routes)
  - `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()`
  - Strip framework/server fingerprinting headers (`X-Powered-By`, detailed `Server` versions; e.g., Express `app.disable('x-powered-by')` or `helmet.hidePoweredBy()`).
- `[OPTIONAL]` **Full Cross-Origin Isolation & XS-Leak Defense (`COOP`/`COEP`):** Pair `Cross-Origin-Resource-Policy: same-origin` and `Fetch Metadata` with `Cross-Origin-Opener-Policy: same-origin` (and `Cross-Origin-Embedder-Policy: require-corp` when `SharedArrayBuffer` or high-precision Spectre/XS-Leak frame-count/timing isolation is needed).

## 5. Session Management, Cookies & CSRF
- `[RED]` **Session Hijacking / Fixation (`CWE-384`, `A07:2025`):** Generate opaque session IDs with >=128 bits CSPRNG entropy; never place session tokens in URLs or `localStorage`. Rotate/regenerate session IDs immediately upon login, MFA step-up, and privilege escalation, and destroy server-side state on logout.
- `[RED]` **Missing CSRF Protection (`CWE-352`):** Require Synchronizer CSRF tokens on state-changing cookie-authenticated endpoints (plus Fetch Metadata `Sec-Fetch-Site` blocking unexpected `cross-site` mutations with `403`). Never perform state mutations on `GET` requests.
- `[YELLOW]` **Weak Cookie Attributes, Parent-Domain Scope & Remember-Me Tokens (RFC 6265bis):** Prefer the `__Host-` cookie prefix: `Set-Cookie: __Host-session_id=<TOKEN>; Secure; HttpOnly; SameSite=Lax; Path=/` (must omit `Domain`; use `SameSite=Strict` for admin panels). Never scope session cookies to a parent domain (`Domain=.example.com`), which allows compromised sibling subdomains to read or shadow cookies. Store long-lived "remember-me" tokens as hashed single-use rotating selector/validator pairs and require fresh step-up re-authentication for sensitive actions.

## 6. SSRF, Redirects, Path Traversal, Archives, XML & Exports
- `[RED]` **SSRF, DNS Rebinding & PDF Renderer SSRF (`CWE-918`, `A01:2025`):** Never fetch arbitrary user URLs directly, including inside HTML-to-PDF renderers (Puppeteer, `wkhtmltopdf`, ReportLab). Allowlist `https://`/`http://` and trusted domains via a standard URL parser, **disable HTTP redirects** (or re-validate every hop), resolve and pin the IP at socket-connect time (preventing TOCTOU **DNS rebinding**) blocking `file://`, loopback (`127.0.0.0/8`, `::1`), link-local/metadata (`169.254.0.0/16`, `fe80::/10`), CGNAT (`100.64.0.0/10`), RFC 1918/ULA, IPv4-mapped IPv6 (`[::ffff:169.254.169.254]`), and decimal/octal/hex IP encodings via an isolated egress proxy, and never return raw upstream responses.
- `[RED]` **Open Redirect (`CWE-601`):** Map opaque IDs to server-side destinations, or allow only relative paths starting with a single `/` (rejecting `//` and `/\`) or exact hostname allowlists.
- `[RED]` **Path Traversal & Zip Slip (`CWE-22`):** Reference stored files by server UUIDs. Where paths or archive extractions (`.zip`/`.tar` `extractall`) are required, decode once, canonicalize (`realpath` / `Path.normalize().toAbsolutePath()`), and enforce strict canonical base-directory prefix containment on every archive entry before writing.
- `[RED]` **XXE & Unsafe File Upload (`CWE-611`, `CWE-434`):** Disable DTDs and external entities (`defusedxml`, `disallow-doctype-decl`) in all XML/SAML/SVG/DOCX parsers. Validate magic bytes + strict extension allowlist (do not trust `Content-Type` or accept active `.svg`/`.html` served inline same-origin), re-encode/CDR untrusted images/docs, rename to UUIDs, enforce byte size + decompression-bomb limits, and store outside web root on an isolated non-executable sandbox origin with `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff`.
- `[YELLOW]` **CSV / Spreadsheet Formula Injection (`CWE-1236`):** Prefix or escape exported cell strings starting with `=`, `+`, `-`, `@`, `\t`, or `\r` before generating CSV/XLSX downloads.
- `[YELLOW]` **Unicode Normalization & Trojan Source (`CWE-172`):** Apply consistent `NFKC` normalization *before* allowlist/uniqueness/authz checks (preventing homoglyph bypasses), and reject bidirectional override characters (`U+202A`–`U+202E`, `U+2066`–`U+2069`) in source files.

## 7. Client Trust, Electron / Webviews & TLS Edge
- `[RED]` **Client Trust Inversion & Client-Side Crypto (`A01:2025`):** Re-validate all inputs, pricing, state transitions, and authorization server-side; never treat UI route guards or hidden form fields as security boundaries, and never ship symmetric decryption keys alongside ciphertext in client JS.
- `[RED]` **Cross-Window `window.postMessage` Origin Bypass (`CWE-346`):** Every `window.addEventListener('message', ...)` handler must enforce exact `event.origin === ALLOWED_ORIGIN` equality (never substring/regex `includes()`/`endsWith()` checks) before trusting `event.data`; never transmit tokens, PII, or sensitive state with wildcard `postMessage(data, '*')`.
- `[RED]` **Insecure Electron / Desktop Webviews:** Explicitly enforce `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`, and `webSecurity: true`. Never expose raw `ipcRenderer` via `contextBridge`; validate IPC senders/arguments in Main, block `will-navigate`/`setWindowOpenHandler`, and allowlist `https://` in `shell.openExternal()`.
- `[RED]` / `[YELLOW]` **TLS & Reverse Proxy Edge:** Reject TLS 1.0/1.1 (`[RED]`); enforce TLS 1.3 and AEAD-only TLS 1.2 (`[YELLOW]` if weak TLS 1.2 suites remain), terminate TLS at proxy/WAF with HTTP->HTTPS `301`, Slowloris timeouts, and TLS/mTLS re-encryption to private origin backends.

## 8. Full-Stack SSR, RSC & Server Actions (Next.js / Vercel)
- `[RED]` **RSC / Hydration Prop Serialization Leakage:** Never pass raw database/ORM user, tenant, or preloaded paywalled/gated content inside React Server Component props or `__NEXT_DATA__` SSR hydration payloads; shape minimal DTOs server-side after authorization so internal flags, hashes, or gated records never ship to the browser.
- `[RED]` **Unauthenticated Server Actions (`'use server'`):** Every Server Action is directly `POST`-reachable. Validate session authentication, authorization, and strict input schemas (e.g., Zod) inside every Server Action and centralized Data Access Layer (DAL)—never rely on hidden UI buttons.
- `[YELLOW]` **Missing `server-only` Guard:** Import `'server-only'` in DB/ORM/secret DAL modules in Next.js App Router so accidental Client Component imports fail at build time.

## 9. DNS, Domain, Email, WebRTC & Edge Protection (Cloudflare / Google / ASVS V17)
- `[RED]` **Cloudflare `Flexible` TLS, Origin-Bypass Exposure & Dangling DNS:** Never run reverse-proxy/CDN edge TLS in `Flexible` mode (leaves edge-to-origin plaintext); enforce **`Full (Strict)`** with verified origin certificates, and lock origin `80`/`443` firewalls strictly to CDN CIDRs or private tunnels (`cloudflared` / PrivateLink) with **Authenticated Origin Pulls (mTLS)** so attackers cannot hit the origin IP directly to bypass WAF/rate-limit rules. Audit and remove orphaned `CNAME`/`A` records pointing to decommissioned cloud services (S3, Heroku, GitHub Pages, Azure) to prevent subdomain takeover (`CWE-350`).
- `[RED]` **WebRTC / TURN Relay SSRF (ASVS V17):** When running WebRTC TURN relays, require ephemeral HMAC credentials and block peer connections to loopback, link-local (`169.254.0.0/16`), and private RFC 1918 subnets.
- `[YELLOW]` **Subresource Integrity (SRI), Third-Party Tag Managers & Email Auth:** Require cryptographic `integrity="sha384-..."` and `crossorigin="anonymous"` on external CDN `<script>`/`<link>` tags, and avoid loading unvetted third-party tag managers, analytics, or chat widgets on auth/login/reset/checkout pages (or isolate them in sandboxed cross-origin iframes). Configure **SPF** (<=10 DNS lookups), **DKIM**, and enforced **DMARC (`p=reject`)** on domains sending transactional mail.
- `[OPTIONAL]` **DNSSEC, CAA, Edge Bot Defense & Proxy Desync/Cache Audits:** Enable **DNSSEC** (registrar DS record) and **CAA** certificate restrictions, configure edge DDoS/Bot Management on auth/checkout routes, and audit CDN-to-origin hops for HTTP Request Smuggling (`CL.TE`/`TE.CL`) and Web Cache Poisoning / Cache Deception (`/profile.css` path confusion, unkeyed `X-Forwarded-Host`).

## Verification Checklist
- Run `scan.py`/`scan.ps1` across both source and compiled frontend bundles (`dist/`, `.next/`, `build/`).
- Probe CORS (`Origin: https://evil.example`, `Origin: null`), headers (`curl -I`), `Set-Cookie` flags, `169.254.169.254` SSRF/redirect payloads, `../` paths, and Electron `BrowserWindow` flags.
- Verify DNS/email posture (`SPF`, `DKIM`, `DMARC p=reject`, `DNSSEC`, `CAA`), absence of dangling CNAMEs, `Full (Strict)` edge TLS, and `integrity=` attributes on external `<script>` tags.
