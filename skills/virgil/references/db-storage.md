# Database, Cache & Object Storage Security

## 1. Query Injection Defense Across Engines
- `[RED]` **SQL Injection, Second-Order SQLi & Stored Procedures (`CWE-89`, `A05:2025`, ASVS V1.2.4):** Bind all data values via prepared/parameterized queries (`?`, `$1`, `:name`, `@param`). Never concatenate or f-string/template-interpolate user input into SQL, HQL/JPQL (`CWE-564`), or `text()`/`createQuery()`, and never concatenate inputs into dynamic SQL inside stored procedures/triggers (`EXECUTE`, `EXECUTE IMMEDIATE`, `sp_executesql` without `sp_executesql @params`). Treat stored DB fields consumed later by admin consoles, batch jobs, or report generators as untrusted input (**second-order SQLi**). Ban `*Unsafe` ORM APIs (`$queryRawUnsafe`, `$executeRawUnsafe`); use safe builders or tagged templates (`prisma.$queryRaw\`...\``).
- `[RED]` **Dynamic Identifier Injection:** When sorting or targeting dynamic columns/tables, map user input strictly through hardcoded server-side allowlist maps/switches before query assembly.
- `[RED]` **NoSQL / ODM Injection (`CWE-943`):** Validate strict scalar types on inputs (reject objects/arrays where strings or ObjectIds are expected) so attackers cannot inject `$ne`, `$gt`, `$regex`, `$where`, `$function`, or `$accumulator`. Enable Mongoose `sanitizeFilter()`/`strictQuery`, strip `$`-prefixed and dotted keys, and disable MongoDB server-side JavaScript (`security.javascriptEnabled: false` or `--noscripting`).
- `[RED]` **Search DSL & LDAP Injection (`CWE-90`):** Build OpenSearch/Elasticsearch queries strictly via typed SDK builders (never string/JSON concatenation). Escape LDAP DNs (RFC 4514) and search filters (RFC 4515).
- `[RED]` **Implicit Type Coercion Traps (`CWE-843`):** Validate strict scalar/numeric/UUID types before querying so implicit engine coercion (e.g., `"123abc"` matching `123` in MySQL, or index-busting casts) cannot bypass lookups or cause full-table scans.

## 2. Database Network Isolation, Transport & Ephemeral Auth
- `[RED]` **Public Database Exposure & Container Firewall Bypass:** Never expose database or search ports (`5432`, `3306`, `1433`, `1521`, `27017`, `6379`, `9200`, `11211`) to `0.0.0.0/0` (`PubliclyAccessible=true`) or public subnets. Restrict security groups strictly to app-tier security groups, bind self-hosted engines to loopback/private interfaces, and in Docker Compose never publish raw host ports (`"5432:5432"` binds `0.0.0.0` and bypasses host `ufw`/`iptables` firewalls—use `"127.0.0.1:5432:5432"` or internal Docker networks only).
- `[RED]` **Exposed DB Admin Consoles & BI Tools:** Never expose `phpMyAdmin`, `Adminer`, `pgAdmin`, or BI/analytics dashboards holding DB credentials on public ingress without VPN/Zero-Trust/SSO + MFA.
- `[RED]` **Unverified or Plaintext DB Transport:** Require server TLS (`ssl = on` + `hostssl` + `scram-sha-256` in PostgreSQL `pg_hba.conf`; `require_secure_transport = ON` in MySQL; `net.tls.mode: requireTLS` in MongoDB). Client connection strings MUST use `sslmode=verify-full` with `sslrootcert` (validates CA chain and hostname). Flag `sslmode=disable|allow|prefer|require` or `rejectUnauthorized: false` as `[RED]`.
- `[YELLOW]` **Static DB Passwords:** Prefer private connectivity (AWS PrivateLink, GCP Cloud SQL Auth Proxy `--auto-iam-authn`) and short-lived IAM database authentication (`rds_iam` 15-min refreshed tokens; GCP `roles/cloudsql.instanceUser`). Never use `trust` or `md5` in `pg_hba.conf`.

## 3. Access Control, Least-Privilege Roles, Multi-Tenancy & BaaS (Supabase / Firebase)
- `[RED]` **Superuser App Connections & Bypassed RLS:** Never connect runtime apps as `postgres`/`root`/`sa`/superuser. Split accounts into `migration_runner` (DDL only), `app_runtime_role` (DML CRUD only, `REVOKE CREATE ON SCHEMA public`, `NOBYPASSRLS`, non-owner of tables), and `analytics_ro` (`SELECT` on replicas/redacted views). On multi-tenant PostgreSQL tables, enable BOTH `ENABLE ROW LEVEL SECURITY` and `FORCE ROW LEVEL SECURITY` (preventing table-owner bypass), failing closed (`NULLIF(current_setting('app.current_tenant', true), '')::uuid`).
- `[RED]` **DB-to-Host Execution, Outbound Calls, Trust Links & Client File Read (`CWE-250`, `CWE-918`, `CWE-73`):** Disable dangerous engine-to-OS and outbound primitives (`xp_cmdshell`, `COPY ... PROGRAM`, `LOAD_FILE`/`INTO OUTFILE` via `secure_file_priv`, untrusted PL extensions, `dblink`, `UTL_HTTP`, and unneeded FDWs / MSSQL linked servers / Oracle DB links), block outbound internet and SMB/UNC egress from DB hosts (preventing NTLM hash coercion via `xp_dirtree`/`xp_fileexist`), and disable MySQL client-side local file reads (`local_infile = 0` on server and `allowLoadLocalInfile=false` / `OPT_LOCAL_INFILE=0` on clients so a rogue server cannot read arbitrary client files via `LOAD DATA LOCAL INFILE`).
- `[RED]` **Pooled Tenant State Bleed (PgBouncer Transaction Mode):** Never set session-level `SET app.current_tenant`. Always bind tenant context inside an explicit transaction using `SET LOCAL` (`set_config('app.current_tenant', $1, true)`).
- `[RED]` **In-Engine Privilege Escalation, `SECURITY DEFINER`, Column Escalation & PostgREST Exposure:** Pin `SET search_path = ''` (or explicit trusted schemas) on every `SECURITY DEFINER` / definer's-rights function, procedure, or trigger and `REVOKE EXECUTE` from `PUBLIC`/`anon` unless explicitly intended. Disable cross-database ownership chaining and untrusted `IMPERSONATE`/`EXECUTE AS`, never grant `CREATEROLE` or `ALTER SYSTEM` to non-DBA roles, never let row `UPDATE` RLS policies expose `is_admin`/`role` columns to user mutation, never trust `raw_user_meta_data` (use `app_metadata` or separate role tables), and move internal tables out of PostgREST-exposed `public` schemas.
- `[RED]` **Firebase Broad Auth Rules:** Reject `allow read, write: if request.auth != null;` or `if true;` on user-owned Firestore/RTDB/Storage paths; require ownership/tenant predicates (`request.auth.uid == resource.data.userId`).
- `[YELLOW]` **RLS Performance:** Wrap Supabase JWT calls in subqueries (`(select auth.uid()) = user_id`) and index RLS foreign-key columns.

## 4. In-Memory Caches, Message Queues & Streaming Brokers (Redis, Memcached, Kafka, RabbitMQ, Pulsar, MQTT)
- `[RED]` **Unauthenticated / Exposed Cache or Broker Protocols (`CWE-306`, `CWE-502`):** Disable Redis `default` user (`user default off`), bind private/loopback interfaces (`protected-mode yes`), require ACL users with scoped commands (`+@read +@write -@dangerous -@admin -eval -evalsha` when Lua is unused) and key prefixes (`~svc_a:*`), enforce TLS (`port 0`, `tls-port 6379`, `tls-replication yes`, `tls-cluster yes`), and patch Redis against `CVE-2025-49844` ("RediShell"). On Memcached, disable UDP (`-U 0`), enable SASL (`-S`) and TLS (`-Z`), and bind internal IP (`-l`). On Kafka (`9092`), RabbitMQ (`5672`/`15672`), MQTT (`1883`), ActiveMQ (`61616`/`8161`), and Pulsar (`6650`), require TLS + SASL/mTLS + authorizer/ACLs (forbid anonymous MQTT, unauthenticated JMX, exposed ZooKeeper without ACLs, and unpatched ActiveMQ OpenWire deserialization). Isolate inter-node cluster ports (RabbitMQ Erlang cookie, Kafka inter-broker/controller, BookKeeper) and never hardcode cluster cookies in images/IaC. Never deserialize untrusted cache or queue payloads with `pickle`/Java `ObjectInputStream`.
- `[RED]` **Broker Extension Hosts, Multi-Tenancy & Cloud Event SSRF:** Authenticate Kafka Connect (`8083`) and Pulsar Function APIs, allowlist connector classes, load connector credentials from external secret providers (never plaintext internal topics), enforce broker-native multi-tenancy (RabbitMQ vhosts, Pulsar tenants, Kafka topic ACLs—not payload-only tenant filtering), and scope EventBridge/Event Grid/PubSub push roles and target destinations.
- `[YELLOW]` **Cache Keys, Broker Integrity, Symmetric Broker JWTs, Offsets & Delayed Job Authz:** Namespace cache keys (`tenant:{id}:resource:{key}`) with bounded TTLs. Prefer asymmetric (`RS256`/`ES256`/`EdDSA`) over shared symmetric `HS256` keys for Pulsar/MQTT broker JWT authentication and forbid deriving per-device IoT keys from a single shared group key. Validate/sign critical business events at consumers, restrict consumer-group offset writes and MQTT retained-message publishing, enforce strict schema validation and DLQ max-receive caps + retention on sensitive DLQs, and re-verify current user permissions when delayed/background jobs execute.

## 5. Object Storage, Network Shares (SMB/NFS), NAS & File Transfer (SFTP/MFT) Hardening
- `[RED]` **Public Bucket Exposure & Unbounded Presigned URLs:** Enable Account/Org Block Public Access (AWS S3 BPA + `Bucket owner enforced`), GCS Public Access Prevention (`storage.publicAccessPrevention` + UBLA), and Azure `AllowBlobPublicAccess = false`. Issue short-TTL (minutes) presigned POST policies / User Delegation SAS constraining `starts-with` key prefix, `Content-Type`, and `content-length-range` from a least-privilege signing identity (never sign arbitrary caller-supplied object keys). Reject non-TLS requests (`aws:SecureTransport: false`) and unencrypted uploads.
- `[RED]` **Insecure Network Shares (SMBv1, Unsigned SMB, NFS `no_root_squash`), Plaintext FTP & Overlapping Roots (`CWE-306`, `CWE-319`, `CWE-250`):** Never expose SMB (`445`), NFS (`2049`/`111`), or FTP (`21`) on public ingress or untrusted networks. Disable `SMBv1`, require **SMB signing** (`RequireSecuritySignature=true`, `server signing = mandatory`) and **SMB 3.x encryption** (`smb encrypt = required`), forbid anonymous/null-session share access (`restrictanonymous`), and never grant `Everyone` / `Authenticated Users` write access on script, deployment, or GPO shares. For NFS, use **NFSv4 with Kerberos (`sec=krb5p`)**, enforce `root_squash` (ban `no_root_squash` and wildcard `*` export hosts), and enforce strict Windows-to-UNIX multi-protocol UID/GID identity mapping on dual-protocol NAS volumes. Retire plaintext FTP (`vsftpd`/`proftpd` with `anonymous_enable=YES`) in favor of chrooted SFTP (`ChrootDirectory`, `ForceCommand internal-sftp`) and never overlap FTP/SFTP/share writable directories with web-served document roots.
- `[YELLOW]` **Upload Malware Quarantine, NAS/Share Hygiene & Ransomware Immutability:** Upload untrusted files to an isolated ingress bucket, scan asynchronously (e.g., Amazon GuardDuty Malware Protection for S3 with object tagging), block reads until `NO_THREATS_FOUND`, and promote clean files to a serving bucket. Enforce KMS/CMEK encryption, versioning, and WORM Object Lock (configured at bucket creation) on backups/audit buckets. Keep NAS/MFT appliances patched with vendor cloud-relay tunnels and optional media/container add-ons disabled, join appliances to enterprise directory MFA/lockout policies, audit share ACL inheritance drift and VSS shadow-copy exposure of deleted secrets, and purge credentials from deployment/unattended answer files (`unattend.xml`, `sysprep.inf`), task sequences, VHD/VMDK images, and GPO preference XML (`cpassword`).

## 6. Backups, Safe Migrations, Query DoS & Soft-Delete Integrity
- `[YELLOW]` **Query Timeouts, `LIKE` Wildcard DoS, Derived-Copy ACL Drift & Soft-Delete/Restore Integrity:** Enforce `statement_timeout` and `idle_in_transaction_session_timeout` on `app_runtime_role` (PostgreSQL) or connection/proxy timeouts (MySQL). Escape `LIKE`/`ILIKE` wildcards (`%`, `_`, `\`) and cap search input lengths (or use `FULLTEXT`/trigram indexes) to prevent full-table-scan CPU exhaustion. Enforce `deleted_at IS NULL` in RLS policies/views rather than ad-hoc query clauses, and use partial unique indexes (`WHERE deleted_at IS NULL` in PostgreSQL; functional expression indexes in MySQL) on soft-deleted unique identifiers. When primary records change ACLs or are deleted/revoked, invalidate derived copies across search indexes, caches, thumbnails, previews, exports, and queued jobs; when restoring backups, undeleting, or rolling back revisions, re-verify current ownership, schema, and authorization so revoked grants are not resurrected.
- `[YELLOW]` **Unencrypted Backups, Cloud Snapshots, Replicas/CDC, External Tables, SQLite & Missing Audit Logs:** Encrypt backups and cloud DB snapshots (RDS/Cloud SQL) with KMS, forbid public/cross-account snapshot sharing (`rds:ModifyDBSnapshotAttribute` locked down), apply primary network/auth/RLS controls to read replicas and Change Data Capture (CDC) replication streams, scope data-warehouse external tables and staging buckets (`COPY INTO`, BigQuery/Snowflake external stages) to dedicated least-privilege storage principals, store server-side SQLite files outside web roots (`0600`, encrypted disk/SQLCipher for sensitive data), isolate backup/BI/data-warehouse exports with Object Lock + WAL/PITR, and run periodic restore drills. Execute schema migrations using expand-and-contract, `CREATE INDEX CONCURRENTLY`, `NOT VALID` + `VALIDATE CONSTRAINT`, and `SET LOCAL lock_timeout = '2s'` / `statement_timeout = '5min'`. Enable `pgAudit` (`pgaudit.log = 'write, ddl'`), MySQL Enterprise Audit (`audit_log`), or MongoDB `auditLog.filter` (alerting on new triggers, scheduled jobs, extensions, and privilege changes), shipping off-host without logging secret/PII bind parameters (`log_min_duration_statement = 0` leakage).

## Verification Checklist
- Audit queries/ORMs for string interpolation, `$queryRawUnsafe`, raw `req.body` passed to MongoDB filters, and `sslmode != verify-full` / `rejectUnauthorized: false`.
- Query `pg_roles` (`rolsuper`, `rolbypassrls`) and `pg_class` (`relrowsecurity`, `relforcerowsecurity`); test concurrent pooled queries across two tenants plus unset tenant context.
- Verify Redis `ACL LIST` (`default off`, `-eval` if unused), S3 BPA / GCS PAP policies, and CI migration rules for `lock_timeout`.
