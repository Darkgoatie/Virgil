# Cloud, Containers, CI/CD, Supply Chain & Security Operations

## 1. Container & Kubernetes Hardening
- `[RED]` **Privileged Containers, Docker Socket & Layer Secrets (`CWE-250`, `CWE-798`):** Never set `privileged: true`, mount `/var/run/docker.sock`, or pass secrets via Dockerfile `ARG`/`ENV`/`COPY` (use BuildKit `--mount=type=secret` and runtime orchestrator stores).
- `[RED]` **Kubernetes Restricted PSS & Unencrypted etcd (`CWE-284`, `CWE-312`):** Enforce `pod-security.kubernetes.io/enforce: restricted` (`runAsNonRoot: true`, `allowPrivilegeEscalation: false`, `readOnlyRootFilesystem: true`, `seccompProfile.type: RuntimeDefault`, `capabilities.drop: ["ALL"]`). Deploy namespace default-deny `NetworkPolicy` (`podSelector: {}`, empty Ingress/Egress) on a policy-enforcing CNI (Cilium/Calico). Scope RBAC to namespaces without `*` wildcards, set `automountServiceAccountToken: false` by default, and configure `kube-apiserver --encryption-provider-config` placing KMS envelope encryption ahead of `identity: {}`.
- `[YELLOW]` **Image Hygiene & Signing:** Use multi-stage builds targeting `distroless`/`scratch` pinned by `@sha256:` digest (never mutable `:latest` tags), declare non-root `USER 65532:65532`, run containers with `--read-only --cap-drop=ALL --security-opt=no-new-privileges:true`, scan images in CI, and sign/verify digests keylessly via **Sigstore Cosign**.

## 2. Cloud IAM, IMDSv2 & Host / Network Perimeter
- `[RED]` **Wildcard Cloud IAM & Open Security Groups (`CWE-269`, `CWE-284`):** Ban `Action: "*"` / `Resource: "*"` in IAM policies; scope roles to explicit actions/ARNs/condition keys (`aws:SourceAccount`, `aws:PrincipalOrgID`), require FIDO2 MFA on root/admins, delete root access keys, and replace static IAM keys with OIDC/STS federation. Never expose management/DB ports (`22`, `3389`, `2375`, `6443`) to `0.0.0.0/0`; use SSM Session Manager, IAP, or WireGuard.
- `[RED]` **IMDSv1 SSRF Exposure (`CWE-918`, CIS AWS EC2.8):** Enforce `HttpTokens: required` (IMDSv2) via Organization SCPs and set `HttpPutResponseHopLimit: 1` where containers must not reach host metadata.
- `[YELLOW]` **Egress Filtering & Host/SSH Hardening:** Constrain outbound egress to approved registries/DNS/proxies; automate OS patching and harden `sshd_config` (`PasswordAuthentication no`, `PermitRootLogin no`, `PubkeyAuthentication yes`, `KbdInteractiveAuthentication no`, `ed25519` keys).

## 3. CI/CD Pipeline & GitHub Actions Security (OWASP CI/CD Top 10)
- `[RED]` **Script Injection & `pull_request_target` RCE (`CICD-SEC-1`, `CICD-SEC-4`, `CWE-78`, `CWE-94`):** Never interpolate `${{ github.event.* }}` (PR titles, branch names, comments, commit messages) inline inside `run:` blocks; always pass via `env:` variables double-quoted (`"$PR_TITLE"`). Use unprivileged `pull_request` for fork builds; never combine `on: pull_request_target` with checking out `github.event.pull_request.head.sha` or running untrusted PR code.
- `[RED]` **Static CI Cloud Keys:** Replace long-lived `AWS_SECRET_ACCESS_KEY` / SA JSON secrets with job-level OIDC (`permissions: id-token: write`) scoped to repo/branch/environment `sub` claims.
- `[YELLOW]` **Mutable Actions, Broad `GITHUB_TOKEN` & Governance (`CICD-SEC-2`, `CICD-SEC-6`):** Pin all third-party `uses:` references to **full 40-char commit SHAs** (`actions/checkout@<40-char-sha> # v4.x.x`), never `@v4` or `@main`. Set explicit workflow-level `permissions: contents: read` (or `{}`), elevating only specific jobs. Require branch protection rulesets (reviews, `CODEOWNERS`, status checks), manual prod environment approvals, and Artifact Attestations / signed releases.

## 4. Software Supply Chain Security (SLSA, Lockfiles, SBOM, Scanning)
- `[RED]` **Hallucinated Packages, Unpinned Installs & Install-Script RCE (`CWE-1395`, `CWE-94`):** Verify every new dependency exists on the official registry with legitimate maintainers before adding (anti-slopsquatting). Reserve internal namespaces (`@company/*`) and pin private upstream registries (anti-dependency-confusion).
- `[YELLOW]` **Deterministic Installs, Lifecycle Scripts, SBOM & SLSA:** Commit lockfiles and use frozen installs in CI/Docker (`npm ci --ignore-scripts`, `pnpm install --frozen-lockfile`, `pip install --require-hashes`, `uv sync --locked`, `cargo build --locked`). Generate resolved **CycloneDX**/**SPDX** SBOMs per release, gate CI with SCA/OSV, SAST (Semgrep/CodeQL), and IaC scanners (Checkov/Trivy), and progress toward **SLSA Build L3** signed provenance + v1.2 Source Track integrity.

## 5. Security Operations & SDLC Lifecycle
- `[YELLOW]` **Threat Modeling, SSDF, WORM SIEM, Disclosure & IR:** Apply **STRIDE** Data Flow Diagrams across trust boundaries for sensitive changes and follow **NIST SSDF (SP 800-218)**. Stream structured sanitized logs off-host to WORM storage (S3 Object Lock) with high-signal alerting. Maintain root `SECURITY.md` and `/.well-known/security.txt` (IETF RFC 9116). Align containment with **NIST SP 800-61 Rev. 3** (revoke tokens and network-isolate compromised workloads *before* termination to preserve volatile forensics).

## 6. Multi-Account Cloud Isolation, Human Access & Drift (AWS Well-Architected / Google Foundations / Microsoft SFI)
- `[RED]` **Shared Prod/Dev Accounts & Standing Human Prod Access:** Isolate `dev`, `staging`, `prod`, and `security/logging` into separate cloud accounts/projects with Organization SCP guardrails. Eliminate standing human SSH/DB access to production data ("keep people away from data"); require automated deployment pipelines or audited time-bound JIT break-glass elevation.
- `[YELLOW]` **Exfiltration Perimeters, Confidential Computing & Drift Detection:** Wrap sensitive data and AI model endpoints in **VPC Service Controls** / private service perimeters, use **Confidential Computing** (encryption in use) for high-sensitivity model weights or regulated inference, and run continuous config/IaC drift detection (AWS Config / Terraform drift checks).

## 7. Memory Safety, Fuzzing & Parser Hardening (Google Safe Coding / Microsoft SDL OneFuzz)
- `[RED]` **Unsafe Native Parsers & Catastrophic ReDoS (`CWE-119`, `CWE-190`, `CWE-1333`):** Audit C/C++/Rust `unsafe`/FFI code handling untrusted bytes for buffer/integer overflows and raw pointer arithmetic. Avoid nested-quantifier regular expressions (`(a+)+`) on untrusted input to prevent CPU exhaustion (ReDoS); use linear-time regex engines (RE2 / Rust `regex`) where available.
- `[YELLOW]` **Compiler Hardening, Sanitizers & Continuous Fuzzing:** Build native binaries with `PIE`/`ASLR`, `FORTIFY_SOURCE`, `-fstack-protector-strong`, and RELRO; run `ASan`/`UBSan` in CI; fuzz all untrusted parsers/decoders continuously (`OSS-Fuzz`, `OneFuzz`, `cargo-fuzz`), and require explicit `// SAFETY:` invariants on every Rust `unsafe` block.

## Verification Checklist
- Run `actionlint`, `zizmor`, or OpenSSF Scorecard (`scorecard`) against repo and `.github/workflows/*.yml`.
- Inspect Dockerfiles/K8s/Terraform manifests for UID 0, `docker.sock`, `:latest`, `*` IAM, `0.0.0.0/0`, `HttpTokens: optional`, shared prod/dev accounts, and missing `USER`/`NetworkPolicy`.
- Confirm CI uses locked installs + `--ignore-scripts`, 40-char Action SHAs, minimal `permissions:`, native sanitizer/fuzz targets where C/C++/Rust `unsafe` exists, and repo includes `SECURITY.md`.
