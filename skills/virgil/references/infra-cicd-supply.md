# Cloud, Containers, CI/CD, Supply Chain & Security Operations

## 1. Container & Kubernetes Hardening
- `[RED]` **Privileged Containers, Docker Socket & Layer Secrets (`CWE-250`, `CWE-798`):** Never set `privileged: true`, mount `/var/run/docker.sock`, or pass secrets via Dockerfile `ARG`/`ENV`/`COPY` (use BuildKit `--mount=type=secret` and runtime orchestrator stores).
- `[RED]` **Kubernetes Restricted PSS, RBAC Escalation Verbs & Unencrypted etcd (`CWE-284`, `CWE-312`):** Enforce `pod-security.kubernetes.io/enforce: restricted` (`runAsNonRoot: true`, `allowPrivilegeEscalation: false`, `readOnlyRootFilesystem: true`, `seccompProfile.type: RuntimeDefault`, `capabilities.drop: ["ALL"]`). Deploy namespace default-deny `NetworkPolicy` (`podSelector: {}`, empty Ingress/Egress) on a policy-enforcing CNI (Cilium/Calico). Scope RBAC to namespaces without `*` wildcards, explicitly restrict privilege-escalation verbs and subresources (`bind`, `escalate`, `impersonate`, `pods/exec`, `pods/attach`, `pods/ephemeralcontainers`, `nodes/proxy`, `tokenrequests`, `mutatingwebhookconfigurations`, `certificatesigningrequests/approval`), set `automountServiceAccountToken: false` by default, and configure `kube-apiserver --encryption-provider-config` placing KMS envelope encryption ahead of `identity: {}`.
- `[YELLOW]` **Image Hygiene & Signing:** Use multi-stage builds targeting `distroless`/`scratch` pinned by `@sha256:` digest (never mutable `:latest` tags), declare non-root `USER 65532:65532`, run containers with `--read-only --cap-drop=ALL --security-opt=no-new-privileges:true`, scan images in CI, and sign/verify digests keylessly via **Sigstore Cosign**.

## 2. Cloud IAM, IMDSv2 & Host / Network Perimeter
- `[RED]` **Wildcard Cloud IAM & Open Security Groups (`CWE-269`, `CWE-284`):** Ban `Action: "*"` / `Resource: "*"` in IAM policies; scope roles to explicit actions/ARNs/condition keys (`aws:SourceAccount`, `aws:PrincipalOrgID`), require FIDO2 MFA on root/admins, delete root access keys, and replace static IAM keys with OIDC/STS federation. Never expose management/DB ports (`22`, `3389`, `2375`, `6443`) to `0.0.0.0/0`; use SSM Session Manager, IAP, or WireGuard.
- `[RED]` **IMDSv1 SSRF Exposure (`CWE-918`, CIS AWS EC2.8):** Enforce `HttpTokens: required` (IMDSv2) via Organization SCPs and set `HttpPutResponseHopLimit: 1` where containers must not reach host metadata.
- `[RED]` **Exposed Debug, Actuator & Profiling Endpoints (`CWE-200`, `CWE-215`):** Block public production exposure of Spring Boot Actuator sensitive endpoints (`management.endpoints.web.exposure.include=*`, `/actuator/heapdump`, `/actuator/env`, `/actuator/mappings`), Go `/debug/pprof`, Django Debug Toolbar, and Laravel Telescope/Ignition. Keep Prometheus `/metrics` (`[YELLOW]` if unauthenticated on public ingress) on internal-only interfaces.
- `[YELLOW]` **Egress Filtering, IAM Policy Analysis, Remote Administration (SSH/RDP/WinRM/VNC), VPN/Bastion & Network Infrastructure (Firewalls/Routers/Switches) Hardening:** Constrain outbound egress to approved registries/DNS/proxies; run automated-reasoning IAM policy checks in CI (e.g., AWS IAM Access Analyzer external + unused-access checks) and prune dormant IAM roles/keys (>90 days unused). Automate OS patching and harden `sshd_config` (`PasswordAuthentication no`, `PermitRootLogin no`, `PubkeyAuthentication yes`, `KbdInteractiveAuthentication no`, `AllowAgentForwarding no`, `AllowTcpForwarding no` on bastions, `StrictHostKeyChecking yes` in automation, modern `ed25519`/AEAD ciphers only, and short-lived SSH user/host certificates over static `authorized_keys`). Keep SSH (`22`), RDP (`3389`), WinRM (`5985`/`5986`), VNC (`5900`), Telnet (`23`, retired), and BMC/IPMI/iDRAC/iLO/console-server out-of-band management planes off public ingress and user VLANs (and block direct-to-host bypass behind VPN/ZTNA/RD Gateways); require RDP **Network Level Authentication (NLA)** + TLS (`UserAuthentication=1`), disable `RestrictedAdmin` where NTLM pass-the-hash is a risk, require WinRM over HTTPS (`AllowUnencrypted=false`) with **JEA** least-privilege endpoints, forbid VNC `SecurityTypes=None`, and keep single-purpose jump hosts free of browser/mail use, clipboard/drive redirection, and forwarded SSH agent sockets. On VPN, ZTNA, and VDI gateways, retire **IPsec IKEv1** and shared group PSKs, keep appliance management interfaces off WAN/tunnel subnets, bind sessions to device certificates with MDM-backed continuous posture checks (never client-asserted registry/file checks alone), lock VPN client profiles against user editing, apply internal firewall segmentation to VPN address pools, and harden VDI/Citrix/Horizon published apps against shell breakout (enforce AppLocker/WDAC, disable unnecessary drive/clipboard/USB redirection, and isolate master-image/broker service accounts). On firewalls, routers, and switches, disable `CDP`/`LLDP` on untrusted/access ports, retire `SNMPv1`/`v2c` (`public`/`private` community strings) and `TFTP` in favor of **`SNMPv3` (`authPriv`)** or streaming telemetry and encrypted SCP/SFTP config backups (banning reversible Cisco `password 7` / `enable password` storage in favor of `secret` Argon2/scrypt/SHA-256 hashes and vault-encrypted config archives), use centralized **TACACS+/RADIUS** per-command AAA + MFA with unique per-device break-glass credentials and factory certs/keys replaced at provisioning, verify signed firmware images + Secure Boot, enforce **DHCP Snooping**, **Dynamic ARP Inspection (DAI)**, **IPv6 RA Guard**, **IP Source Guard**, and `passive-interface default` on access switchports, authenticate interior/first-hop/exterior routing (**OSPF/IS-IS/HSRP/VRRP cryptographic auth** and **BGP TCP-AO/MD5 + GTSM max-hop + RPKI/prefix filtering**), firewall the out-of-band console network, and protect TLS-inspection CA private keys and SPAN/mirroring sessions under Tier-0 change control.
- `[RED]` **Active Directory, LDAP, Kerberos & Enterprise PKI / Certificate Authority Escalation Paths (when directory services or PKI are present, `CWE-287`, `CWE-269`, `CWE-295`):** Forbid anonymous or plaintext LDAP simple binds (`ldaps://` or StartTLS required; enforce **LDAP signing** and **LDAP channel binding** plus **SMB signing** to stop NTLM relay). Disable `LLMNR`, `NetBIOS-NS`, `mDNS`, and `WPAD`, and require **secure-only dynamic DNS updates**. In Kerberos/AD, disable `RC4` encryption (`AES256` only), require Kerberos pre-authentication on all principals (preventing **AS-REP Roasting**), use **gMSAs** or >=25-char random passwords on SPN accounts (preventing **Kerberoasting**), disable **Unconstrained Delegation** (and audit Constrained / Resource-Based Constrained Delegation `msDS-AllowedToActOnBehalfOfOtherIdentity`), set `ms-DS-MachineAccountQuota = 0`, place privileged users in `Protected Users` with **Tier-0 administrative isolation**, audit `AdminSDHolder` / `DCSync` replication ACLs (`DS-Replication-Get-Changes-All`) / GPO & `SYSVOL` write permissions / `DnsAdmins`, stop `Spooler` on Domain Controllers, deploy encrypted **Windows LAPS**, enforce **SID filtering** on forest trusts, twice-rotate `krbtgt` keys on schedule, and harden **AD CS & Enterprise PKI** against `ESC1`–`ESC13`: forbid caller-supplied SANs (`ENROLLEE_SUPPLIES_SUBJECT` / `EDITF_ATTRIBUTESUBJECTALTNAME2`), retire V1 templates and "Any Purpose"/subordinate-CA EKUs, restrict Enrollment Agents and group-linked OID issuance policies, require HTTPS with Extended Protection (`EPA` channel binding) and RPC encryption on enrollment endpoints, enforce strong SID certificate mapping (`KB5014754` full enforcement; audit `altSecurityIdentities`), verify exact EKU + issuance policy on VPN/API/802.1X relying parties, protect CA/HSM keys as Tier-0 with role separation and hardware-backed KRA escrow keys, bind SCEP challenges to identity, scope ACME DNS-01 tokens to dedicated `_acme-challenge` subzones, and never bake test root CAs into production trust stores.

## 3. CI/CD Pipeline & GitHub Actions Security (OWASP CI/CD Top 10)
- `[RED]` **Script Injection, `pull_request_target` RCE & CI Cache/Artifact Poisoning (`CICD-SEC-1`, `CICD-SEC-4`, `CWE-78`, `CWE-94`):** Never interpolate `${{ github.event.* }}` (PR titles, branch names, comments, commit messages) inline inside `run:` blocks; always pass via `env:` variables double-quoted (`"$PR_TITLE"`). Use unprivileged `pull_request` for fork builds; never combine `on: pull_request_target` with checking out `github.event.pull_request.head.sha` or running untrusted PR code, and never let lower-trust PR/fork jobs populate caches, workspaces, or build artifacts that a privileged release job later restores and executes or publishes.
- `[RED]` **Default & Weak Service Credentials (`CWE-798`):** Never deploy databases, Redis, Elasticsearch, message queues, or orchestration/admin dashboards with default or hardcoded passwords (`admin`, `changeme`, `password`, `123456`). Require strong CSPRNG or vault-managed credentials in IaC/Compose/Helm charts.
- `[RED]` **Static CI Cloud Keys & CI Log Secret Leaks (`CWE-532`):** Replace long-lived `AWS_SECRET_ACCESS_KEY` / SA JSON secrets with job-level OIDC (`permissions: id-token: write`) scoped to repo/branch/environment `sub` claims. Never run `set -x` (`xtrace`), `env`, `printenv`, or `echo` on secret values in CI steps; mask any dynamic token via `::add-mask::`.
- `[YELLOW]` **Mutable Actions, Broad `GITHUB_TOKEN` & Governance (`CICD-SEC-2`, `CICD-SEC-6`):** Pin all third-party `uses:` references to **full 40-char commit SHAs** (`actions/checkout@<40-char-sha> # v4.x.x`), never `@v4` or `@main`. Set explicit workflow-level `permissions: contents: read` (or `{}`), elevating only specific jobs. Require branch protection rulesets with sensitive-path `CODEOWNERS`/multi-reviewer policy checks (e.g., `policy-bot` on IAM, auth, and `.github/workflows/`), manual prod environment approvals, and Artifact Attestations / signed releases.

## 4. Software Supply Chain Security (SLSA, Lockfiles, SBOM, Scanning)
- `[RED]` **Hallucinated Packages, Dependency Confusion & Install-Script RCE (`CWE-427`, `CWE-1395`, `CWE-94`):** Verify every new dependency exists on the official registry with legitimate maintainers before adding (anti-slopsquatting). Prevent **Dependency Confusion** by reserving internal namespaces (`@company/*`), pinning scoped registries (`.npmrc` `@scope:registry=...`), and banning Python `pip --extra-index-url` for private packages (use `--index-url` pointing to a private mirroring proxy instead, as `--extra-index-url` resolves higher versions from public PyPI).
- `[YELLOW]` **Deterministic Installs, Digest Promotion, Updater Rollback & SLSA:** Commit lockfiles and use frozen installs in CI/Docker (`npm ci --ignore-scripts`, `pnpm install --frozen-lockfile`, `pip install --require-hashes`, `uv sync --locked`, `cargo build --locked`), bind test, signing, and release promotion to the same immutable artifact digest (never re-resolve by mutable tag/filename), verify software updater metadata (product, channel, platform, expiry, and anti-rollback version floor) alongside payload signatures, and use **OIDC Trusted Publishing** instead of static `NPM_TOKEN`/`PYPI_API_TOKEN`. Generate resolved **CycloneDX**/**SPDX** SBOMs per release, gate CI with SCA/OSV, SAST (Semgrep/CodeQL), and IaC scanners (Checkov/Trivy), and progress toward **SLSA Build L3** signed provenance.

## 5. Security Operations & SDLC Lifecycle
- `[YELLOW]` **Threat Modeling, SSDF, WORM SIEM, Disclosure & IR:** Apply **STRIDE** Data Flow Diagrams across trust boundaries for sensitive changes and follow **NIST SSDF (SP 800-218)**. Stream structured sanitized logs off-host to WORM storage (S3 Object Lock) with high-signal alerting. Maintain root `SECURITY.md` and `/.well-known/security.txt` (IETF RFC 9116). Align containment with **NIST SP 800-61 Rev. 3** (revoke tokens and network-isolate compromised workloads *before* termination to preserve volatile forensics).

## 6. Media Parsers, ReDoS & Systems / Language Safety (Chromium Rule of 2, Oracle Java SE, Microsoft .NET/GSL, AWS s2n-tls)
- `[RED]` **Catastrophic ReDoS, Chromium "Rule of 2" & FFI / Binary-Loader / Double-Fetch Flaws (`CWE-1333`, `CWE-119`, `CWE-190`, `CWE-426`):** Avoid nested-quantifier regular expressions (`(a+)+`) on untrusted input; prefer linear-time regex engines (RE2 / Rust `regex`). Per **Google Chromium's Rule of 2**, no component may combine all three of: (1) *untrustworthy inputs* (complex grammars/network bytes), (2) *unsafe implementation language* (`C`/`C++`/`asm` or unencapsulated `unsafe` blocks), and (3) *high privilege* (unsandboxed process). Parse untrusted formats in a memory-safe language (`Rust`, Java, Go) or reduce privilege via `seccomp`/sandboxed utility processes (`cloudflare/foundations`, `nsjail`) and normalize into simple structures before crossing IPC. Ban unsafe C string/buffer functions (`gets`, `strcpy`, `strcat`, `sprintf`, `vsprintf`), verify FFI pointer-length/ownership/layout contracts and forbid panics/exceptions unwinding across `extern "C"` ABIs, block untrusted `LD_LIBRARY_PATH`/`RPATH`/DLL/plugin search-order paths (bind signature verification to the mapped file descriptor), and copy user/shared memory once in kernel/ioctl/IPC parsers to prevent **double-fetch** TOCTOU races.
- `[RED]` **Unsafe .NET / Java Deserialization, Remoting, JNI & Finalizer Attacks (`CWE-502`):** Per **Microsoft .NET Secure Coding Guidelines**, ban `BinaryFormatter`, `SoapFormatter`, `NetDataContractSerializer`, `LosFormatter`, `ObjectStateFormatter`, `.NET Remoting`, `DCOM`, and obsolete Code Access Security (`CAS` / `AllowPartiallyTrustedCallersAttribute` / `[SecurityTransparent]`); isolate untrusted code with OS users, AppContainers, or Hyper-V containers and audit P/Invoke / COM wrappers. Per **Oracle Java SE Secure Coding Guidelines**, ban untrusted `ObjectInputStream.readObject()` / `readUnshared()` / `XMLDecoder` (or enforce strict `ObjectInputFilter` allowlists), validate buffer lengths across JNI native boundaries, prevent finalizer attacks on partially constructed classes (`final` classes or pre-constructor checks), and defensively copy mutable inputs/outputs.
- `[YELLOW]` **Sandboxed Media/Document Parsers (`nsjail`) & Exact Classpath Hygiene:** Run ImageMagick, Ghostscript, FFmpeg, and LibreOffice against untrusted user files inside isolated `nsjail`/`seccomp` sandboxes with restrictive `policy.xml`. On JVM/polyglot builds, enforce explicit direct dependencies (`baseline-exact-dependencies`), classpath duplicate detection (`baseline-class-uniqueness`), and reproducible archive ordering (**Palantir Gradle Baseline**).

## 7. Optional / Enterprise-Scale Cloud, Cluster Runtime & Systems Controls
- `[OPTIONAL]` **Multi-Account Cloud Isolation, Security Zones, JIT & BeyondCorp Access:** Separate `dev`, `staging`, `prod`, and `security/logging` into distinct cloud accounts/projects with SCPs and immutable Security Zones (blocking public buckets/unencrypted volumes at creation), replace standing human prod SSH/DB access with audited JIT break-glass elevation + device-posture-aware Zero Trust (`BeyondCorp`), wrap sensitive AI/data workloads in VPC Service Controls / Confidential Computing, and enable automated IaC/config drift detection.
- `[OPTIONAL]` **Binary Authorization, `in-toto`, Cluster Admission, Service Mesh & eBPF Runtime Enforcement:** Enforce deploy-time **Binary Authorization** / Cosign / **`in-toto`** supply-chain layout attestations (proving peer review + trusted CI provenance), deploy **OPA Gatekeeper** or **Kyverno** admission controllers, Layer-7 **Service Mesh** (Istio/Linkerd/Cilium) mTLS authorization, and kernel-level **eBPF** runtime syscall detection and enforcement (**Falco** / **Cilium Tetragon**).
- `[OPTIONAL]` **Native Compiler Hardening, C++ GSL, s2n-tls Macros, Kani, Infer/Pysa & TigerStyle / NASA JPL Discipline:** Build C/C++ binaries with OpenSSF compiler hardening flags (`-fPIE -pie`, `-D_FORTIFY_SOURCE=3`, `-fstack-protector-strong`, `-Wl,-z,relro,-z,now`, CFI) and zero warnings (`-Wall -Wextra -Werror`); use **C++ Core Guidelines** & **Microsoft GSL** (`gsl::span`, `gsl::not_null`, `gsl::narrow`, RAII) or **AWS `s2n-tls`** cursor/blob bounds macros (`RESULT_ENSURE*`, `RESULT_CHECKED_MEMCPY`, non-swappable/zeroed secret buffers); encapsulate Rust `unsafe` behind small precondition-documented safe APIs verified with **Kani Rust Verifier** (`#[kani::proof]`), `ASan`/`UBSan`, and continuous fuzzing (`OSS-Fuzz`/`OneFuzz`/`cargo-fuzz`); run compositional static/taint analyzers (**Meta Infer** and **Meta Pysa**); apply **TigerBeetle (`TigerStyle`)** & **NASA JPL (`Power of 10`)** safety-critical rules (no recursion, fixed loop/queue upper bounds, explicit-width integer types `u32`/`uint32_t`, paired positive/negative-space assertions, zeroed buffer padding against buffer bleeds) and **Uber Go Style** goroutine/slice discipline; and enforce signed Git commits (`gitsign` / SSH / GPG).

## Verification Checklist
- Run `actionlint`, `zizmor`, or OpenSSF Scorecard (`scorecard`) against repo and `.github/workflows/*.yml`.
- Inspect Dockerfiles/K8s/Terraform manifests for UID 0, `docker.sock`, `:latest`, `*` IAM, `0.0.0.0/0`, `HttpTokens: optional`, shared prod/dev accounts, and missing `USER`/`NetworkPolicy`.
- Confirm CI uses locked installs + `--ignore-scripts`, 40-char Action SHAs, minimal `permissions:`, native sanitizer/fuzz targets where C/C++/Rust `unsafe` exists, and repo includes `SECURITY.md`.
